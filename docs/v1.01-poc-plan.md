# Agenty v1.01 POC 计划

> 状态：已被 `dev_plans/legacy-v1.01/PRD.md` 取代；此前“验证通过”仅针对单项目文件结构探索，不代表当前多 Agent POC 完成
>
> `v1.01` 是本轮 POC 的工作里程碑名称。正式发布版本号将在 POC 验收后确定。

## 1. 背景

v1.0 设计草案确立了以 Agent 为中心的项目模型，并提出由三个核心文件与三个核心文件夹构成 agent suite。

v1.01 不试图一次实现完整运行时，而是先验证最基础的工程假设：agent suite 能否被可靠创建、识别、检查和记录操作。

## 2. POC 目标

建立一个可以从命令行运行的最小闭环：

1. 创建符合约定的项目骨架和 agent suite；
2. 检查 agent suite 的结构与关键数据是否有效；
3. 读取 `MEMORY.json` 中的快速记忆摘要；
4. 将 Agent 操作以事件形式追加到 `agent_log.jsonl`；
5. 用自动化测试证明以上行为可重复执行。

## 3. 非目标

本轮 POC 不包含：

- 对接任何 LLM；
- bullet 或 messenger 的通信协议；
- trigger 调度；
- session 恢复引擎；
- memory 检索或向量化；
- 技能发现、安装和执行；
- 多 Agent 协作；
- 权限审批和沙箱；
- 远程服务或图形界面。

## 4. 用户故事

### US-01：初始化项目

作为项目创建者，我可以运行一条命令创建项目骨架，使项目从一开始就包含标准 agent suite。

### US-02：检查 Agent

作为项目维护者，我可以检查 agent suite 是否完整，并快速看到 Agent 名称、关键事实数量和事件数量。

### US-03：记录事件

作为 Agent 运行时，我可以将一次重要操作记录为结构化事件，供后续审计、记忆提取和恢复使用。

## 5. 命令设计

```bash
# 创建 PROJECT_NAME/agent-suite 与 PROJECT_NAME/project
agenty init PROJECT_NAME --name project-agent

# 检查结构和快速记忆
agenty inspect PROJECT_NAME

# 追加一条事件记录
agenty event PROJECT_NAME task.started --message "start the first task"
```

命令应同时支持人类可读输出和失败时的非零退出码。

## 6. POC 数据约定

### 6.1 `MEMORY.json`

POC 使用最小结构：

```json
{
  "schema_version": 1,
  "agent": {
    "name": "project-agent",
    "purpose": "Develop, manage, and maintain this project."
  },
  "facts": [],
  "updated_at": "2026-01-01T00:00:00Z"
}
```

### 6.2 `agent_log.jsonl`

每行是一个独立 JSON 事件：

```json
{"schema_version":1,"timestamp":"2026-01-01T00:00:00Z","event":"suite.initialized","message":"Agent suite initialized"}
```

POC 阶段只规定最小公共字段，不提前设计完整事件分类体系。

### 6.3 Git 边界

POC 暂定以下内容不进入 Git：

- `agent-suite/skills/user_skills/`
- `agent-suite/memory/`
- `agent-suite/sessions/`
- `agent-suite/agent_log.jsonl`

`AGENTS.md`、`MEMORY.json` 和基础 `skills/` 参与 Git。该选择是为了验证共享定义与本地运行状态分离的思路，不代表最终方案。

## 7. 验收标准

- [x] `agenty init` 能创建三个文件和三个文件夹；
- [x] 重复初始化默认安全失败，不覆盖已有 suite；
- [x] Agent 名称经过校验，不能写入非法或空名称；
- [x] `MEMORY.json` 是有效 JSON，并包含最小必要字段；
- [x] `agenty inspect` 能发现缺失文件、无效 JSON 和错误字段；
- [x] `agenty inspect` 在 suite 有效时返回成功状态；
- [x] `agenty event` 每次只追加一行有效 JSON；
- [x] 事件包含版本、UTC 时间、事件名和可选消息；
- [x] POC 在 Python 3.10 及更高版本可以启动；
- [x] 核心行为具有自动化测试。

## 8. 成功判定

如果上述验收标准全部通过，则认为 agent suite 的文件系统表达可以作为下一阶段运行时的基础。

下一阶段才进入 memory 生命周期、session 接续、技能发现与回归，以及 bullet/agent worker 适配层的设计。

### 验证结果

- Python 3.10：7 项自动化测试通过；
- Python 3.14：7 项自动化测试通过；
- CLI `init → event → inspect` 端到端流程通过；
- source distribution 与 wheel 构建通过；
- Python 3.10 缺少 `tomli` 导致 CLI 无法启动的问题已修复。

## 9. 风险与待验证假设

- 固定使用 `agent-suite/` 是否适合已有项目；
- `MEMORY.json` 是否应该由人、Agent 或二者共同维护；
- JSONL 是否足以支持未来的并发写入和事件查询；
- 本地状态全部位于项目目录内是否会造成体积和隐私问题；
- 单 Agent 目录模型是否能自然扩展到多 Agent；
- Git 忽略规则是否应由 Agenty 自动维护。
