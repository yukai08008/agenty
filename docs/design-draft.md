# Agenty v1.0 设计草案

> 状态：已被 `dev_plans/legacy-v1.01/PRD.md` 取代，保留作为早期讨论记录
>
> 本文记录 Agenty v1.0 当前已经形成的设计共识，用于后续讨论和迭代。文中标记为“待确定”的内容尚未成为最终设计。

## 1. 项目定位

Agenty 是一个以 Agent 为中心的项目开发、管理和维护工具。

这里的 Agent 不是一次模型调用、一个聊天窗口或一段临时 Prompt，而是项目中的长期一等实体。它具有明确的引导、能力、记忆、会话和行为记录，可以持续参与项目开发与维护，并随着实践积累经验。

Agenty 的目标是为不同应用形态提供统一的 Agent 基础模型和运行时，再由应用层根据任务类型、交互方式和责任边界进行分化。

## 2. 统一的 Agent 运行时

dual-tmux 的 bullet 与 messenger 的 agent worker，本质上都是以 Agent 为核心的运行时。二者应遵循统一的基础设计，并以 `AGENTS.md` 作为核心引导。

### 2.1 bullet

bullet 主要面向单个项目的长期开发和维护：

- 任务执行时间可能较长，甚至跨越多个阶段；
- 需要持续理解项目状态并维护上下文；
- 主要处理技术性工作，需要暴露更完整、细致的执行信息；
- 通常由 trigger 或项目事件驱动，而不是完全依赖人直接发起；
- 更强调连续性、可恢复性和长期责任。

### 2.2 agent worker

messenger 驱动的 agent worker 主要面向短周期、事务性的执行任务：

- 通常需要在较短时间内完成处理并返回结果；
- 通过消息进行任务分发和结果回传；
- 输出内容可能更多面向业务侧或非技术用户；
- 更强调及时响应、边界明确和结果交付。

### 2.3 二者关系

bullet 与 agent worker 的差异主要属于应用层：

- 驱动方式不同；
- 联络和通信方式不同；
- 任务持续时间不同；
- Agent 在任务中承担的责任不同；
- 输出信息的对象和粒度不同。

它们在 Agent 的身份、能力、记忆、会话、日志和启动机制上存在大量重合，因此底层不应分别建立互不兼容的 Agent 模型。

## 3. Agent suite

一个完整的 Agent 由一套 agent suite 表达。agent suite 由三个核心文件和三个核心文件夹组成：

```text
agent-suite/
├── AGENTS.md
├── MEMORY.json
├── agent_log.jsonl
├── skills/
│   └── user_skills/
├── memory/
└── sessions/
```

### 3.1 `AGENTS.md`

`AGENTS.md` 是 Agent 的 bootstrap，也是事实标准和必要引导。

它负责告诉运行时如何认识、启动和约束这个 Agent，包括但不限于：

- Agent 的身份与职责；
- Agent 的工作边界；
- 项目约定和工作方式；
- 如何载入关键记忆、详细记忆和技能；
- 如何记录行为与维护自身状态。

### 3.2 `MEMORY.json`

`MEMORY.json` 由 `AGENTS.md` 引导生成或维护，保存少量关键事实，作为 Agent 最快速的记忆入口。

它的目标不是容纳全部历史，而是让 Agent 在启动或恢复时能够迅速获得高价值、强确定性的信息，从而提高反应速度和准确性。详细经验和历史信息应进入 `memory/`。

### 3.3 `skills/`

`skills/` 保存 Agent 可复用的能力和连续操作方法，是 Agent 能力的主要体现，也是经验沉淀的一种形式。

基础技能参与 Git 版本管理，以便随项目共享、审查和演进。

`user_skills/` 保存用户或本地环境特有的技能，不参与 Git。它与基础技能的覆盖、合并和优先级规则待确定。

### 3.4 `memory/`

`memory/` 保存大量记忆细节，是 Agent 长期经验的基础，不参与 Git。

与 `MEMORY.json` 相比，`memory/` 更完整，但读取和检索成本也更高。Agent 应先从 `MEMORY.json` 获得关键事实，再按任务需要检索详细记忆。

### 3.5 `agent_log.jsonl`

`agent_log.jsonl` 保存 Agent 的事件级操作日志。Agent 的重要操作都应在这里留下痕迹，用于：

- 了解 Agent 做过什么；
- 调试和定位问题；
- 审计操作过程；
- 从历史行为中提取记忆和经验；
- 为技能演化和回归提供依据。

日志的事件结构、保留策略以及是否参与 Git，待后续确定。

### 3.6 `sessions/`

`sessions/` 保存会话和事务接续信息，不参与 Git。

session 本质上也是 memory，但它具有严格的时序约束，主要用于恢复尚未完成的事务、保持任务执行的连续性，以及在进程或运行环境变化后继续工作。

## 4. 智能的构成

agent suite 从推理与记忆两个方面构成一个完整的智能体：

```text
引导与约束
    + 关键事实
    + 可复用能力
    + 长期经验
    + 时序上下文
    + 行为痕迹
```

对应关系如下：

| 智能组成 | 主要载体 |
| --- | --- |
| 引导与约束 | `AGENTS.md` |
| 关键事实 | `MEMORY.json` |
| 可复用能力 | `skills/` |
| 长期经验 | `memory/` |
| 时序上下文 | `sessions/` |
| 行为痕迹 | `agent_log.jsonl` |

这些组成部分共同使 Agent 能够跨任务和跨时间保持连续性，而不是每次运行都从零开始。

## 5. 项目目录

当前设想的项目结构如下：

```text
PROJECT_NAME/
├── agent-suite/
├── project/
└── .git/
```

- `agent-suite/` 保存 Agent 的定义、能力和运行状态；
- `project/` 保存 Agent 所开发和维护的项目代码树；
- `.git/` 为整个项目提供版本管理边界。

agent suite 与项目代码处于同一个项目边界内，但保持结构上的独立。是否支持多个 agent suite，以及目录名称是否固定，待后续确定。

## 6. 技能体系

技能不是简单的工具清单或 Prompt 片段，而是 Agent 为完成某类任务形成的、可组合且可连续执行的方法。

### 6.1 元技能

Agent 至少需要以下技能管理能力：

- 技能检索；
- 技能载入；
- 技能创建与修改；
- 技能删除。

这些能力使 Agent 能够维护和演进自身的能力集合。

### 6.2 基础技能

基础技能至少包括：

- 命令行执行；
- 文件操作；
- 浏览器操作；
- Git 操作。

当运行时使用 OpenCode、Codex 等客户端时，客户端可能已经提供部分基础能力。Agenty 需要区分运行时原生能力与 agent suite 中定义的技能，避免重复建设，同时保持统一的能力表达。

### 6.3 技能回归

技能应当具有回归样例，用于自检。

回归样例用于验证技能在以下变化发生后是否仍然有效：

- 技能内容发生修改；
- 项目环境或依赖发生变化；
- 底层 Agent 客户端或模型发生变化；
- 多个技能进行组合；
- Agent 从历史经验中更新技能。

因此，技能应当是一种可版本化、可验证、可演进的能力模块。

## 7. 初步设计原则

根据当前讨论，Agenty v1.0 应遵循以下原则：

1. **Agent 优先**：项目围绕 Agent 的长期运行和演进进行组织。
2. **统一内核，应用分化**：bullet 与 agent worker 共享基础模型，在应用层适配不同任务。
3. **约定优于隐藏状态**：核心结构通过清晰的文件和目录表达。
4. **快速记忆与详细记忆分层**：关键事实和长期细节采用不同载体。
5. **能力可以积累**：技能是 Agent 经验的可复用表达。
6. **能力必须可验证**：技能需要回归样例和自检机制。
7. **执行可以接续**：session 应支持事务在时间和进程之间延续。
8. **行为可以追溯**：重要操作必须形成事件级记录。
9. **共享定义与私有状态分离**：进入 Git 的项目能力与本地运行状态保持明确边界。

## 8. 待讨论问题

以下内容尚未形成最终结论：

- `MEMORY.json` 是否参与 Git，以及哪些信息允许共享；
- `agent_log.jsonl` 是否参与 Git，以及日志的轮转和归档策略；
- `user_skills/` 与基础技能的覆盖和优先级规则；
- 一个项目是否允许存在多个 Agent，以及 Agent 之间如何协作；
- agent suite 的目录名称和位置是否固定；
- memory、session 和 log 的具体数据格式；
- trigger 的定义、发现、调度和恢复机制；
- Agent 权限、安全边界和人工审批机制；
- 技能回归样例的格式与执行协议；
- 如何适配 Codex、OpenCode 等不同 Agent 客户端；
- bullet 与 messenger agent worker 的具体通信协议。
